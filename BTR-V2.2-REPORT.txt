LOCKED FAILURES ADDRESSED

1. FAMILY SETUP LINK / INITIAL CONNECTION
Observed:
Safari setup followed by Add to Home Screen still led the standalone PWA to request the long family code.

Root issue addressed:
The previous script consumed and removed ?connect= immediately in Safari. That could remove the provisioning token before the standalone Home Screen launch had a chance to use the same setup URL.

Repair:
- Safari now keeps ?connect= in the setup URL.
- The standalone PWA consumes the token and then removes it from its own visible URL.
- Existing localStorage/cookie recovery remains.
- Manual family-code entry remains recovery-only.

REAL-DEVICE LIMIT:
Whether iOS launches the installed PWA with the setup URL depends on the installed web-app/start-url behavior. This cannot be proven in the current environment. If BTR-v2.2 still requires the code on a truly fresh install, eliminating that final step requires a backend pairing mechanism (or exposing the private family credential, which this build deliberately does not do).

2. ACTIVE SITTER ALERT ON REOPEN
Observed:
sitter.active remained true, but the caretaker alert did not reliably return after the app was swiped away/reopened.

Repair:
- Removed heartbeat/focus-loop complexity.
- Fresh pageshow, foreground return, and startup now explicitly force the sitter entry alert when sitter.active is true.
- The explicit check resets the foreground-dismissed flag.
- Active state/storage logic itself was left intact.

3. SITTER "RE-ACTIVATE" FRICTION
Observed:
Active sitter mode displayed Re-activate updated directions.

Repair:
- Active sitter mode no longer shows the activation button.
- Save draft updates the directions while active.
- End sitter directions remains the explicit off switch.

4. TEMPORARY CARETAKER CHECKLIST
Observed:
An individual sitter checkbox briefly checked and then reset when the sitter view rerendered.

Root issue:
renderSitterView rebuilds the checkbox HTML after sync/render activity.

Repair:
- Temporary checklist selections are stored in an in-memory Set for the current app session.
- Each sitter checklist row has a stable key.
- Rerenders restore checked state.
- These temporary checks do not sync into Frannie's shared record.

5. BLACK SCREEN AFTER MODALS
Observed:
Closing/using modal UI sometimes left a black surface until another touch.

Repair:
- Removed the forced document transform/repaint workaround.
- Modal cleanup now only restores normal body overflow.
- Existing backdrop-blur removal remains.
This intentionally reduces iOS WebKit compositing manipulation.

6. INTERMITTENT SHOW PREVIOUS DRAWERS
Observed:
History drawers could work, then appear unresponsive after later renders/sync.

Repair:
- Drawer open/closed state is stored by history group.
- When Care rerenders after sync, an open drawer remains open rather than instantly collapsing and appearing to ignore the tap.
- Button-driven drawers remain in place.

7. RECENT SHARED CHANGES
Previous architecture retained:
- append-only merge by activity ID
- explicit Care actions call setNextActivity
- actor/date/time rendering

Additional repair:
- addActivity now explicitly requests another sync pass itself.
This prevents an audit entry created during an in-flight state transition from depending solely on the outer persist path to schedule delivery.
